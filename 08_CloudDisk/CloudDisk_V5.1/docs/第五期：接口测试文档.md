# CloudDisk 第五期：接口测试文档

本文档用于测试当前 Web 网盘项目的 HTTP API。

你的当前使用方式是：

```text
Linux 服务器 IP：192.168.193.128
CloudDisk 网关端口：8888
Windows 浏览器访问：http://192.168.193.128:8888
```

浏览器测试适合验证页面能否正常使用，但不方便构造异常请求。例如：

```text
1. 故意不传 Content-Type。
2. 故意少传字段。
3. 故意传错误 token。
4. 故意访问不存在的文件 id。
5. 故意用错误密码登录。
```

所以建议增加两类测试：

```text
1. 在 Linux 服务器本地用 curl 测试。
2. 在 Windows 上用 Postman 测试。
```

也可以进一步补充：

```text
3. 编写自动化接口测试脚本。
```

---

## 一、测试前准备

### 1. 启动项目

在 Linux 服务器中进入项目目录：

```bash
cd /home/lws/my_project/Cpp_Advanced/课件/05_Web网盘项目/CloudDisk
```

构建项目：

```bash
./build.sh
```

启动项目：

```bash
./run.sh
```

如果启动成功，应该能看到类似日志：

```text
RabbitMQ is ready.
[AuthService] listening on 9001
[UserService] listening on 9002
[FileMetaService] listening on 9003
[OssUploadWorker] started
```

如果启用了 Consul，并且 Consul 可用，还会看到：

```text
[Consul] registered AuthService-127.0.0.1-9001
[Consul] registered UserService-127.0.0.1-9002
[Consul] registered FileMetaService-127.0.0.1-9003
```

### 2. 确认服务可访问

在 Linux 服务器本地执行：

```bash
curl -i http://127.0.0.1:8888/
```

在 Windows 浏览器访问：

```text
http://192.168.193.128:8888/
```

如果 Windows 无法访问，优先检查：

```text
1. Linux 服务器防火墙是否放行 8888。
2. 虚拟机网络是否能从 Windows 访问 192.168.193.128。
3. CloudDisk server 是否正在运行。
```

## 三、认证接口测试

### 1. 注册成功

每次测试建议换一个新用户名，避免用户名重复。

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_001","password":"123456","confirm":"123456"}'
```

预期：

```text
HTTP/1.1 201 Created
```

响应体类似：

```json
{
  "status": "success",
  "message": "注册成功",
  "data": {
    "userId": 1,
    "username": "curl_user_001"
  }
}
```

### 2. 重复注册

再次执行同一个用户名：

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_001","password":"123456","confirm":"123456"}'
```

预期：

```text
HTTP/1.1 409 Conflict
```

响应体类似：

```json
{
  "status": "error",
  "message": "用户名已存在"
}
```

### 3. 注册时两次密码不一致

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_bad_confirm","password":"123456","confirm":"654321"}'
```

预期：

```text
HTTP/1.1 400 Bad Request
```

响应体类似：

```json
{
  "status": "error",
  "message": "两次输入的密码不一致"
}
```

### 4. 注册时缺少字段

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d '{"username":"","password":"123456","confirm":"123456"}'
```

预期：

```text
HTTP/1.1 400 Bad Request
```

响应体类似：

```json
{
  "status": "error",
  "message": "用户名和密码不能为空"
}
```

### 5. 注册时 Content-Type 错误

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: text/plain" \
  -d '{"username":"curl_user_wrong_type","password":"123456","confirm":"123456"}'
```

预期：

```text
HTTP/1.1 400 Bad Request
```

响应体类似：

```json
{
  "status": "error",
  "message": "请求格式有误"
}
```

### 6. 登录成功

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_001","password":"123456"}'
```

预期：

```text
HTTP/1.1 200 OK
```

响应体中应包含：

```json
{
  "status": "success",
  "message": "登录成功",
  "data": {
    "accessToken": "...",
    "tokenType": "Bearer",
    "user": {
      "userId": 1,
      "username": "curl_user_001"
    }
  }
}
```

### 7. 保存登录 token

如果服务器安装了 `jq`，可以用下面命令自动保存 token：

```bash
TOKEN=$(curl -s -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_001","password":"123456"}' \
  | jq -r '.data.accessToken')

echo "$TOKEN"
```

如果没有安装 `jq`，可以手动复制登录响应里的 `accessToken`，然后执行：

```bash
TOKEN="这里替换成你的 accessToken"
```

### 8. 登录密码错误

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"curl_user_001","password":"wrong_password"}'
```

预期：

```text
HTTP/1.1 401 Unauthorized
```

响应体类似：

```json
{
  "status": "error",
  "message": "用户名或密码错误"
}
```

### 9. 登录用户不存在

```bash
curl -i -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d '{"username":"not_exists_user","password":"123456"}'
```

预期：

```text
HTTP/1.1 401 Unauthorized
```

响应体类似：

```json
{
  "status": "error",
  "message": "用户名或密码错误"
}
```

## 四、用户接口测试

```bash

  -H "Authorization: Bearer $TOKEN"
```

```json
  "status": "success",
```

## 七、下载接口测试

### 1. 下载成功

前提：`FILE_ID` 是当前用户已经上传成功的文件 ID。

```bash
curl -i -X GET "$BASE_URL/api/v1/file/$FILE_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -o /tmp/downloaded_cloud_disk_test.txt
```

注意：

```text
curl 使用 -i 和 -o 同时输出时，响应头也可能写入文件。
如果要保存纯文件内容，建议使用下面的命令。
```

保存纯文件内容：

```bash
curl -L -X GET "$BASE_URL/api/v1/file/$FILE_ID" \
  -H "Authorization: Bearer $TOKEN" \
  -o /tmp/downloaded_cloud_disk_test.txt
```

查看下载结果：

```bash
cat /tmp/downloaded_cloud_disk_test.txt
```

预期：

```text
hello cloud disk test
```

### 2. 下载不存在的文件 ID

```bash
curl -i -X GET "$BASE_URL/api/v1/file/999999" \
  -H "Authorization: Bearer $TOKEN"
```

预期：

```text
HTTP/1.1 404 Not Found
```

响应体类似：

```json
{
  "status": "error",

}
```

## 八、Consul 注册中心测试

### 1. 检查 Consul 是否可用

```bash
curl -i http://127.0.0.1:8500/v1/status/leader
```

如果 Consul 正常，会返回类似：

```text
HTTP/1.1 200 OK
"172.17.0.2:8300"
```

如果返回连接失败，说明 Consul 没有正常启动。

### 2. 查询已注册服务

```bash
curl -s http://127.0.0.1:8500/v1/catalog/services
```

预期包含：

```json
{
  "AuthService": ["cloud-disk", "srpc"],
  "UserService": ["cloud-disk", "srpc"],
  "FileMetaService": ["cloud-disk", "srpc"]
}
```

### 3. 查询健康 AuthService 实例

```bash
curl -s "http://127.0.0.1:8500/v1/health/service/AuthService?passing=true"
```

预期能看到 `ServiceAddress` 和 `ServicePort`：

```json
[
  {
    "Service": {
      "Service": "AuthService",
      "Address": "127.0.0.1",
      "Port": 9001
    }
  }
]
```

### 4. 测试 Consul 不可用

临时关闭 Consul，或者把 `.env` 中 Consul 地址改错：

```env
CONSUL_HTTP_ADDR=http://127.0.0.1:18500
```

重新启动项目。

预期：

```text
1. run.sh 检查 Consul 失败。
2. 项目不继续启动 auth_service/user_service/filemeta_service/server。
3. 终端打印 Consul service is not ready 相关错误。
```

## 十、推荐的第三种测试方式：自动化脚本

curl 和 Postman 适合手动测试。

如果要反复验证项目是否正常，建议写一个自动化脚本，例如：

```text
tests/api_smoke_test.sh
```

脚本可以自动执行：

```text
1. 注册用户。
2. 登录并提取 token。
3. 不带 token 访问 /user/me，确认返回 401。
4. 带 token 访问 /user/me，确认返回 200。
5. 上传文件，保存 fileId。
6. 获取文件列表，确认返回 200。
7. 下载文件，确认内容一致。
8. 请求不存在文件，确认返回 404。
```

示例脚本：

```bash
#!/bin/bash
set -e

BASE_URL=${BASE_URL:-http://127.0.0.1:8888}
USERNAME="smoke_$(date +%s)"
PASSWORD="123456"
TEST_FILE="/tmp/cloud_disk_smoke.txt"
DOWN_FILE="/tmp/cloud_disk_smoke_download.txt"

echo "hello smoke test" > "$TEST_FILE"

echo "[1] register"
curl -s -f -X POST "$BASE_URL/api/v1/auth/register" \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"$USERNAME\",\"password\":\"$PASSWORD\",\"confirm\":\"$PASSWORD\"}" >/dev/null

echo "[2] login"
TOKEN=$(curl -s -X POST "$BASE_URL/api/v1/auth/login" \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"$USERNAME\",\"password\":\"$PASSWORD\"}" \
  | jq -r '.data.accessToken')

if [ -z "$TOKEN" ] || [ "$TOKEN" = "null" ]; then
  echo "login failed: token is empty"
  exit 1
fi

echo "[3] unauthorized /user/me should be 401"
STATUS=$(curl -s -o /tmp/no_auth_resp.json -w "%{http_code}" "$BASE_URL/api/v1/user/me")
test "$STATUS" = "401"

echo "[4] authorized /user/me should be 200"
STATUS=$(curl -s -o /tmp/me_resp.json -w "%{http_code}" \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/v1/user/me")
test "$STATUS" = "200"

echo "[5] upload file"
FILE_ID=$(curl -s -X POST "$BASE_URL/api/v1/files" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@$TEST_FILE" \
  | jq -r '.data.fileId')

if [ -z "$FILE_ID" ] || [ "$FILE_ID" = "null" ]; then
  echo "upload failed: fileId is empty"
  exit 1
fi

echo "[6] list files should be 200"
STATUS=$(curl -s -o /tmp/files_resp.json -w "%{http_code}" \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/v1/files")
test "$STATUS" = "200"

echo "[7] download file"
curl -s -f -L \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/v1/file/$FILE_ID" \
  -o "$DOWN_FILE"

diff "$TEST_FILE" "$DOWN_FILE"

echo "[8] missing file should be 404"
STATUS=$(curl -s -o /tmp/missing_file_resp.json -w "%{http_code}" \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/v1/file/999999")
test "$STATUS" = "404"

echo "API smoke test passed."
```

使用方式：

```bash
chmod +x tests/api_smoke_test.sh
BASE_URL=http://127.0.0.1:8888 tests/api_smoke_test.sh
```

注意：

```text
这个脚本依赖 jq。
如果服务器没有 jq，可以先安装 jq，或者手动解析 token。
```

## 十一、建议测试顺序

推荐按下面顺序测试：

```text
1. 浏览器测试页面基本功能。
2. Linux curl 测试所有正常接口。
3. Linux curl 测试错误请求。
4. Windows Postman 测试跨机器访问。
```
