# CloudDisk 项目目录结构说明

第四期微服务改造后，项目按职责拆分目录，避免所有源码和生成文件堆在根目录。

```text
CloudDisk/
├── CMakeLists.txt
├── build.sh
├── run.sh
├── .env
├── README.md
├── bin/
├── build/
├── docs/
├── proto/
├── rpc_gen/
├── src/
│   ├── common/
│   ├── gateway/
│   ├── services/
│   └── worker/
└── www/
```

## 根目录

根目录只放项目级入口文件：

```text
CMakeLists.txt  CMake 构建配置
build.sh        编译脚本，会重新生成 protobuf/srpc 代码
run.sh          一键启动脚本
.env            OSS、RabbitMQ 等环境变量
README.md       第三期说明文档
```

## src/common

公共 C++ 模块：

```text
CryptoUtil.*            密码哈希、文件 hash、JWT
OssStorage.*            OSS 上传下载封装
RabbitMqOssUploader.*   RabbitMQ 上传任务发布/消费
ServiceCommon.*         微服务共用 MySQL 和工具函数
```

## src/gateway

API Gateway：

```text
main.cc
CloudDiskServer.h
CloudDiskServer.cc
```

网关负责 HTTP、静态资源、请求解析、响应封装、文件上传下载字节流，以及调用后端 srpc 服务。

## src/services

三个 srpc 微服务入口：

```text
AuthServiceMain.cc      注册、登录、Token 校验
UserServiceMain.cc      用户资料查询
FileMetaServiceMain.cc  文件元数据查询和写入
```

## src/worker

后台 worker：

```text
OssUploadWorkerMain.cc
```

它负责消费 RabbitMQ 上传任务，并调用 OSS 上传文件。

## proto

手写 Protobuf IDL：

```text
cloud_disk.proto
```

## rpc_gen

由 `protoc` 和 `srpc_generator` 生成的 RPC 代码：

```text
cloud_disk.pb.h
cloud_disk.pb.cc
cloud_disk.srpc.h
client.pb_skeleton.cc
server.pb_skeleton.cc
```

这个目录里的文件不要手动改。需要改 RPC 接口时，修改 `proto/cloud_disk.proto`，然后执行：

```bash
./build.sh
```

## bin

编译生成的可执行程序：

```text
server
auth_service
user_service
filemeta_service
oss_upload_worker
```

`run.sh` 会启动这些程序。

## docs

项目文档，例如第四期设计文档和目录说明。

## www

前端静态资源。
